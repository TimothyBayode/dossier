## Your first hour, in order

1. `npm install` (if `node_modules` is missing or the earlier install died).
2. `npm test`, expect nine suites and 79 passing tests. Fix anything red before
   touching anything else; a red service test usually means a stub in
   `tests/service.test.js` no longer matches the service, not a bug in the
   domain.
3. `npm run check`, every shipped file parses.
4. The icon and the vendored bridge already exist. Regenerate them only if you
   change the mark or the bridge version: `npm run make:icon`, then
   `npm run build:bridge`.
5. `forge register`, writes the real app id over the
   `REPLACE_WITH_FORGE_REGISTER` placeholder in `manifest.yml`. There is no CLI
   flag for the app name; it prompts. This is the only step that needs the
   owner's Atlassian account.
6. `forge deploy -e development` (the bridge is already built and committed).
7. Install on a real site and open the issue panel once. Then
   `forge logs -e development -s 10m -n 200` to distinguish "nothing linked"
   from "query refused", the graph fails silently by design.

## Decisions the plan leaves open

- **Name.** "Dossier" is the working name. It is short, the product literally
  compiles dossiers, and `find-owners` is about tickets rather than people.
  Not checked against existing Atlassian Marketplace apps or domains, do that
  before anything goes public.
- **One write, or none.** `publish-dossier` exists because a human-auditable
  brief is a real product point, but if the write scope worries a reviewer it
  can be cut and the app becomes read-only with a four-tool surface. Nothing
  else in the code depends on it.
- **Confluence.** The dossier is Jira-only. Multi-product exposure (a Confluence
  page's content) requires the multi-product app compatibility path, which is
  Preview and adds a consent step. Out of scope unless someone funds it.

## Environment notes for a phone-based build

- `/tmp` does not exist on Termux; use `$PREFIX/tmp/opencode`.
- Detach anything over ~30 s (`setsid nohup … > log 2>&1 < /dev/null &`); the
  host restarts under memory pressure and a foreground run dies with it.
- The pure tests need no dependencies. Only `service.test.js` needs
  `@forge/api` (it imports `src/platform/jira.js` through the service).
- `scripts/check.mjs` parses with esbuild, the same parser Forge bundles with -
  it catches duplicate declarations that `node --check` misses.
